# I18N.md — German & English (ADR-10)

- `values/strings.xml` = English (default), `values-de/strings.xml` = German. Same keys, CI check (T-005 script `tools/check_strings.py`).
- Per-app language: `AppCompatDelegate.setApplicationLocales` + `locales_config.xml` (de, en). Setting `app_language` = system/de/en.
- German style: **du**, short sentences, no anglicisms when a normal German word exists ("Einstellungen", "Gedächtnis", "Herunterladen"). English: plain, friendly.
- Plurals via `<plurals>`. Dates/numbers via `java.time` + `Locale` (never hand-format). Decimal comma in DE.
- Answer language: setting `answer_language` = auto / de / en (`ReplyLanguagePolicy` in `:core-llm`, see LLM.md §9).
  - The **whole system prompt** is in the answer language: `system_full.de.txt` for `de`, and for `auto` on a German device; `system_full.en.txt` otherwise. A 1.7B model follows the language of its system prompt far more than a rule inside an English prompt (device test 03.11.: English prompt → English or DE/EN mixed answers to German messages).
  - The prompt ends with a short language rule (`# Sprache` / `# Language`).
  - Every turn gets a one-line system hint right before the answer (`Antworte auf Deutsch.` / `Answer in English.`), placed after the history so the cached prompt start stays valid. For `auto` the language comes from a tiny stop-word detector on the last user message (umlauts count double); unclear messages like "Hi" fall back to the device language.
- Voice/STT/TTS packs follow app language; both can be installed.
- Tool results stay language-neutral JSON; tool texts (weather codes) use app language.
- Pim's lines live in strings too (`pim_greeting_1..5`), random pick.

- **Antwortsprache (03.11.2026):** Standard „Wie meine Nachricht“: Pim antwortet in der Sprache der letzten eindeutigen Nutzernachricht, egal welche Sprache (Erkennung offline, siehe LLM.md). Feste Einstellung Deutsch/English bleibt möglich.
